문제 1 — 교환신청 도구 추가

요구사항

code/ch30_final.py를 복사해 code/ch30_ex_exchange.py를 만드세요.

  • @tool로 request_exchange(order_id: str, reason: str) -> str 를 정의해, 교환 접수번호(예: EX- + 난수)를 만들어 반환한다.
  • build_agent의 tools에 추가한다.
  • SYSTEM_PROMPT에 교환 요청 시 이 도구를 쓰라고 명시한다.
  • 기대 결과: "주문 O000050 불량이라 교환하고 싶어" 입력 시 에이전트가 request_exchange를 호출하고 접수번호가 답변에 포함된다.

왜 하나? 지금까지의 도구는 읽기(조회) 만 했습니다. 교환신청은 쓰기(행동) 도구입니다 — 18강에서 배운 "읽기 도구 vs 쓰기 도구"의 실전. 도구를 하나 추가하는 것만으로 에이전트의 능력이 확장됨을 봅니다.

해답

# code/ch30_ex_exchange.py (ch30_final.py 기반, 추가분만 표시)
import random, string
from langchain_core.tools import tool

# 기존 ch30_final 의 도구·빌더 로직을 가져와 확장
# (여기서는 핵심 추가분만; 실제로는 ch30_final.py 전체를 복사 후 수정)

@tool
def request_exchange(order_id: str, reason: str) -> str:
    """[추가] 주문에 대한 교환을 접수하고 접수번호를 반환한다.

    order_id: 교환할 주문번호, reason: 교환 사유.
    """
    # 접수번호 생성 (EX- + 영숫자 6자리)
    suffix = "".join(random.choices(string.ascii_uppercase + string.digits, k=6))
    ticket = f"EX-{suffix}"
    # (실무에선 여기서 DB에 교환 접수 기록을 INSERT)
    return (f"교환 접수가 완료되었습니다. 접수번호: {ticket}\n"
            f"주문 {order_id} / 사유: {reason}\n"
            f"영업일 기준 1~2일 내 담당자가 연락드립니다.")


SYSTEM_PROMPT = (
    "너는 승승장구몰의 통합 CS 상담원이다. 친절한 한국어로 답하라.\n"
    "- 주문 상태는 get_order_status, 재고는 get_stock, 자주 묻는 질문은 search_faq,\n"
    "  환불/교환/멤버십 정책은 policy_search 도구를 사용하라.\n"
    "- 고객이 '교환하고 싶다/교환 신청'을 요청하면 request_exchange 도구로 접수하라.\n"  # 추가
    "- 정책 질문은 반드시 policy_search 결과로만 답하고, 모르면 모른다고 하라.\n"
    "- 이전 대화 맥락을 기억해 이어서 답하라."
)


def build_agent():
    from langchain.agents import create_agent
    from langgraph.checkpoint.memory import InMemorySaver
    llm = get_chat(provider=cfg["llm"]["provider"], temperature=cfg["llm"]["temperature"])
    tools = [get_order_status, get_stock, search_faq,
             request_exchange,                         # ← 교환 도구 추가
             build_policy_tool()]
    agent = create_agent(llm, tools=tools, system_prompt=SYSTEM_PROMPT,
                         checkpointer=InMemorySaver())
    return agent


if __name__ == "__main__":
    print(answer("주문 O000050 불량이라 교환하고 싶어. 화면이 안 켜져.", thread_id="ex-1"))

예상 출력

교환 접수가 완료되었습니다. 접수번호: EX-K7P2QM
주문 O000050 / 사유: 화면이 안 켜지는 불량
영업일 기준 1~2일 내 담당자가 연락드립니다.

관찰 포인트

  • 에이전트가 "교환하고 싶어"를 보고 request_exchange 도구를 선택했습니다(시스템 프롬프트 지시 + 도구 독스트링).
  • 도구를 하나 추가하고 프롬프트에 한 줄 더했을 뿐인데 능력이 확장됐습니다.
  • 이건 쓰기(행동) 도구 — 실무에선 DB INSERT가 일어나므로, 비가역 행동엔 사람 승인(human-in-the-loop)을 두는 게 안전합니다(07번).

문제 2 — 메모리 격리 검증 스크립트

요구사항

code/ch30_ex_memory.py를 작성하세요.

  • answer()를 사용해:
  • ① thread_id="A"로 "내 이름은 오지표야" → "내 이름이 뭐였지?"를 연속 호출 → 두 번째 답에 "오지표"가 들어가는지(메모리 유지).
  • ② thread_id="B"로 "내 이름이 뭐였지?"를 물었을 때는 기억하지 못하는지(스레드 격리).
  • 검증: 콘솔에 "메모리 유지: PASS/FAIL", "스레드 격리: PASS/FAIL" 두 줄 출력.

왜 하나? 메모리가 제대로 작동하는지, 그리고 세션이 격리되는지를 자동으로 검증합니다. 멀티 사용자 서비스에서 "A의 대화가 B에게 새는" 일이 없어야 하죠(19강).

해답

# code/ch30_ex_memory.py
# 실행: python code/ch30_ex_memory.py
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from ch30_final import answer       # 통합 에이전트 진입점 재사용


def test_memory_retention() -> bool:
    """① 같은 thread 안에서 이름을 기억하는가."""
    answer("내 이름은 오지표야. 기억해줘.", thread_id="A")     # 이름 알려주기
    reply = answer("내 이름이 뭐였지?", thread_id="A")          # 같은 thread → 기억해야
    print(f"  [A] 회상 응답: {reply}")
    return "오지표" in reply


def test_thread_isolation() -> bool:
    """② 다른 thread 에서는 그 이름을 모르는가(격리)."""
    reply = answer("내 이름이 뭐였지?", thread_id="B")          # 다른 thread → 몰라야
    print(f"  [B] 회상 응답: {reply}")
    return "오지표" not in reply        # 이름이 없으면 격리 성공


if __name__ == "__main__":
    print("=" * 60)
    print("메모리 격리 검증")
    print("=" * 60)
    retention = test_memory_retention()
    isolation = test_thread_isolation()
    print("-" * 60)
    print(f"메모리 유지: {'PASS' if retention else 'FAIL'}")
    print(f"스레드 격리: {'PASS' if isolation else 'FAIL'}")

예상 출력

============================================================
메모리 격리 검증
============================================================
  [A] 회상 응답: 고객님의 성함은 오지표님이십니다.
  [B] 회상 응답: 죄송하지만 성함을 알려주신 적이 없습니다. 다시 알려주시겠어요?
------------------------------------------------------------
메모리 유지: PASS
스레드 격리: PASS

관찰 포인트

  • 메모리 유지(A): 같은 thread에서 이름을 기억 → "오지표" 포함 → PASS.
  • 스레드 격리(B): 다른 thread는 A의 대화를 모름 → "오지표" 없음 → PASS.
  • thread_id로 대화가 완전히 분리됩니다 — 멀티 사용자 서비스의 필수 조건(19강).
  • 이런 자동 검증 스크립트가 평가의 기초입니다(09번 확장의 "평가 자동화").

마무리 — 그리고 수료를 축하합니다 🎉

  • 문제 1: 쓰기 도구(request_exchange)를 추가해 에이전트를 확장했습니다 — 도구 하나로 능력이 늘어남.
  • 문제 2: 메모리 유지·스레드 격리를 자동 검증했습니다 — 신뢰할 수 있는 멀티 사용자 서비스의 조건.

30강을 완주하며 여러분은 LLM 호출 → 도구 → 루프 → RAG → 메모리 → 멀티에이전트 → 설계·배포 → 통합까지 에이전트 개발의 전 과정을 직접 구현했습니다. 1강에서 "답 못 했던" 질문을, 30강의 에이전트는 실제 데이터를 조회해 답합니다.
